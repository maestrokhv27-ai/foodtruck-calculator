# AI Context — ERP Фудтрака

Этот файл содержит контекст проекта для ИИ-ассистентов (Claude, GPT, Cursor и т.д.).

## 🎯 О проекте

ERP-система для управления фудтраком в GTA 5 RP. Помогает игрокам считать закупку, готовить блюда, продавать через POS-терминал и вести учёт.

## 🏗️ Архитектура

### Модульная структура
- **core/** — ядро системы (не трогать без необходимости)
  - `EventBus.js` — событийная шина (pub/sub)
  - `Storage.js` — безопасная обёртка над localStorage
  - `Store.js` — единое хранилище состояния с авто-сохранением
  
- **data/** — данные
  - `constants.js` — константы (цены, рецепты, названия)
  - `menu.js` — база блюд (DISH_DATABASE)
  
- **features/** — бизнес-логика (каждая фича независима)
  - `Settings.js` — настройки и выбор меню
  - `Inventory.js` — склад сырья и заготовок
  - `Procurement.js` — расчёт закупки
  - `Workstation.js` — POS-терминал, касса, рецепты, брак
  - `Report.js` — отчёт по смене
  
- **app.js** — точка входа, инициализация модулей, утилиты UI
- **index.html** — только HTML-разметка
- **css/styles.css** — все стили

### Принцип работы

1. **Store** — единственный источник правды. Все данные хранятся там.
2. **EventBus** — модули общаются через события, не зная друг о друге.
3. **Storage** — автоматическое сохранение в localStorage при изменении Store.

### Поток данных

Пользователь → UI → Store.set() → EventBus.emit() → другие модули реагируют
↓
Storage.set() → localStorage

```javascript
{
    businessLogic: '1' | '2' | '3' | '4',  // режим работы
    truckFridge: number,                    // лимит фудтрака (кг)
    carTrunk: number,                       // лимит багажника авто
    rvStorage: number,                      // лимит багажника автодома
    rvCabinet: number,                      // лимит шкафа автодома
    marginPercent: number,                  // наценка %
    fishPrice: number,                      // цена рыбы
    
    selectedDishes: { [index: number]: boolean },  // выбранное меню
    rawStock: { [item: string]: number },          // сырьё
    prepStock: {                                   // заготовки
        truck: { [item: string]: number },
        rvStorage: { [item: string]: number },
        rvCabinet: { [item: string]: number }
    },
    
    shift: { revenue, profit, orders },     // статистика смены
    waste: { total, items: [] },            // списание брака
    currentOrder: { [dishIndex: number]: qty },  // текущий заказ
    
    calculatedPrices: { [idx]: price },     // рассчитанные цены
    calculatedCosts: { [idx]: cost }        // рассчитанная себестоимость
}
🔑 Ключевые события (EventBus)
store:ready — Store загружен из localStorage
state:{key}:changed — изменилось конкретное поле
state:changed — любое изменение состояния
state:reset — полный сброс
procurement:calculate — запрос на пересчёт закупки
procurement:calculated — закупка рассчитана
🍳 Бизнес-логика
Режимы работы
Только фудтрак — всё в одном месте
Фудтрак + авто — сырьё в багажнике авто
Максимальная цепочка — авто + кемпер + фудтрак
Автодом + фудтрак — сырьё в автодоме
Цепочка приготовления
Сырьё → Заготовки → Блюда
Сырьё покупается в магазине 24/7
Заготовки готовятся из сырья (хлеб, котлеты, фарш и т.д.)
Блюда собираются из заготовок
Масло и тесто
НЕ закупаются — готовятся из молока / муки+яйца
В расчёте закупки разбиваются на базовое сырьё
В цепочке приготовления показываются как промежуточные компоненты
⚠️ Важные правила при разработке
Не используй глобальные переменные — только через Store
Не вызывай функции других модулей напрямую — используй EventBus
Все изменения состояния — только через Store.set()
UI обновляется через подписку на события, не через прямой вызов
Добавляя новое поле в Store — добавь его в init() и reset()
Новая фича = новый файл в features/ + регистрация в app.js
🧪 Тестирование
Поскольку это браузерное приложение без бэкенда:
Проверяй в DevTools → Console
localStorage можно очистить через DevTools → Application
Для сброса состояния: Store.reset() в консоли
